# 云端速递 · Cloud Express

![cover](docs/cover.png)

`云端速递`（Cloud Express）是一个 NeoForge 的整合包更新模组，配一个自建的 TCP 服务端：
玩家在游戏标题界面点一下「检查更新」，缺哪个文件下哪个，不用再重下整个整合包。

![NeoForge](https://img.shields.io/badge/NeoForge-20.4%20~%2026.2-orange)
![License](https://img.shields.io/badge/License-MIT-green)
![Server](https://img.shields.io/badge/server-Python%203-3776ab)

> 代码有相当一部分是 AI 帮忙写的，功能我逐项在自己服务器上测过、也一直挂着用。
> 如果你要拿去做正式服，建议先自己过一遍；跑出问题欢迎提 Issue。

## 它是什么，不是什么

一句话：**服主改完整合包内容，玩家不用重新下载整个包。**

以前改一个模组版本，服主要重新打包传网盘，玩家得重下几个 G。现在服主在服务器上换掉那一个文件、
把版本号加一，玩家进游戏点一下按钮就同步好了——只传变化的部分。

它不是启动器，不管整合包安装，也不碰 `config/`、存档和服务端数据。
它只认三类文件：`mods/*.jar`、`shaderpacks/*.zip`、`resourcepacks/*.zip`，其他一律不管。

## 有什么

**玩家这边**

- 标题界面多一个「检查更新」按钮，启动时会静默比对版本，有新版本按钮变绿
- 只下变化的文件，靠 SHA-1 比对内容（改文件名不会导致重下）
- 下载后先校验再替换，失败自动重试；更新失败不会把你的整合包搞坏
- **只动文件名带 `_ZAKO` 的云端文件**——你自己塞进去的模组、光影、资源包不会被删
- 需要和云端严格对齐时，右上角锤子可以「修复客户端」（会删掉多余文件，动手前有确认页）
- 旧版本文件不会一直堆着，更新完的下一次启动自动清掉
- v3.0.0 起，标题界面的「检查更新」按钮**点右键**能改更新服务器地址

**服主这边**

- 服务端是单个 `server.py`（Python 3，双击就能跑），不用装数据库不用配环境
- 启动时自动给分发文件补 `_v<版本>_ZAKO` 尾缀，你只管往里丢文件
- 下载并发有限流，不怕玩家一窝蜂同时更新
- v3.0.0 起自带一个网页管理端，浏览器里就能传文件、改版本号、看日志

## 玩家：三步开玩

1. 按游戏版本下好对应的 jar，丢进 `.minecraft/mods/`
2. 确认更新服务器地址——**如果服主把整合包和配置一起发给你了，这一步可以跳过**
3. 进游戏，标题界面点「检查更新」

第一次启动会生成 `config/speedupdate/server.json`：

```json
{
  "host": "127.0.0.1",
  "tcpPort": 10086
}
```

默认是本机地址，连别人的服要改。不想翻文件的话：进游戏，在标题界面的「检查更新」按钮上**点右键**，
会出来一个填写地址和端口的小窗口，里面有「测试」按钮，连得上会显示服务器的内容版本。

## 服主：把服务端跑起来

服务端就是一个 Python 文件，不需要额外依赖。jar 里也带了一份，客户端首次启动会释放到
`config/speedupdate/server.py`，可以直接拿来用。

**Windows**

1. 把 `server.py` 放到你想放的地方（比如 `D:\speedupdate\`），双击运行
2. 首次启动会自动生成 `speedupdate.conf` 和三个目录：`mods/`、`shaderpacks/`、`resourcepacks/`
3. 需要放行防火墙端口：`10086`（玩家更新）和 `10010`（网页管理端）

**Linux**

```bash
# 装个 Python 3 就行，然后直接跑
python3 server.py

# 想常驻的话，用 screen / systemd 之类的自己挂一下
screen -S speedupdate
python3 server.py
# Ctrl+A 然后 D 退出，进程继续跑
```

启动后会打印横幅，能看到端口、版本号、管理端地址，照着看就行。

## 服主日常：发一次更新

1. 把新文件丢进对应的目录（`mods/`、`shaderpacks/`、`resourcepacks/`）
2. 进网页管理端改内容版本号，或者直接改 `speedupdate.conf` 里的 `version` 然后重启服务端
3. 顺手在 `Changelog.txt` 里写两行更新说明——这段文字会原样显示在玩家的更新窗口里
4. 完事

服务端每次启动会检查一遍文件，需要补尾缀的自动补上，然后重建哈希清单，不用你管。

玩家那边的表现：进游戏发现按钮变绿了，点一下，看到你写的更新日志，点「立刻更新」，
只下变了的文件，下完提示重启。

> [!WARNING]
> 更新过程中别关游戏。真中断了也没关系：版本号是最后才写的，没写完就当这次没更新过，重来一次就行。

## 网页管理端（v3.0.0 起）

服务端跑起来后，浏览器打开 `http://你的服务器IP:10010`，输入密码就能用。
默认密码是 `12345678`，写在 `speedupdate.conf` 的 `admin_password` 里。

能做的事：上传 / 重命名 / 删除分发文件、改内容版本号和更新日志、改配置、看运行日志和管理日志、
一键「重新加载」（等于重跑一遍启动流程，不用重启进程）。

- 登录状态保持 24 小时，服务端一重启就全部失效
- 同一个 IP 密码输错 5 次会锁 5 分钟
- 端口设成 `0` 可以直接关掉管理端，只留玩家更新服务

> [!WARNING]
> 管理端和玩家更新走的是同一套监听配置。如果你把 `bind_v4` 设成了 `0.0.0.0`，管理端也会暴露在公网——
> 上线第一件事是把默认密码改掉，别用 `12345678`。

## 配置一览

**服务端 `speedupdate.conf`**

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `port` | `10086` | 玩家连接的 TCP 端口 |
| `version` | `1.0.000` | 整合包内容版本，客户端据此判断要不要更新 |
| `bind_v4` | `0.0.0.0` | IPv4 监听地址，管理端也跟着走 |
| `enable_v6` | `true` | 是否监听 IPv6 |
| `max_downloads` | `10` | 同时下载的玩家数上限（1~64） |
| `feedback_url` | `https://chat.deepseek.com/` | 客户端「反馈问题」按钮跳哪 |
| `admin_port` | `10010` | 网页管理端端口，`0` = 关闭 |
| `admin_password` | `12345678` | 管理端密码，明文存的，随时可改 |

**客户端 `config/speedupdate/server.json`**

| 字段 | 默认值 | 说明 |
|---|---|---|
| `host` | `127.0.0.1` | 更新服务器地址（IP 或域名都行） |
| `tcpPort` | `10086` | 服务端 `port` 对应的端口 |

## 常见问题

**点了检查更新，一直提示连不上服务器**

先确认服务端在跑、端口放行了。然后用按钮右键进设置页，地址填好点一下「测试」，
它会告诉你卡在哪：域名解析失败、连接被拒、还是超时。

**玩家自己装的模组会被删掉吗**

不会。正常更新只认文件名带 `_ZAKO` 的云端文件，其他文件它看都不看。
除非你自己点了「修复客户端」——那个模式会严格对齐云端，动手前有确认页。

**`_ZAKO` 是什么意思**

云端文件的身份标记。服务端往你丢进去的文件名后面加 `_v<版本号>_ZAKO`，
客户端只管理带这个标记的文件。所以别手动把尾缀删掉，删了客户端就不认它了。

**文件名变了，玩家要重下吗**

不用。比对的是文件内容的 SHA-1，不看名字。你给模组升级、改名、换代理，
只要内容没变，玩家那边一个字节都不会重下。

**服务端管理端密码忘了**

不用找回，直接改文件。打开 `server.py` 同目录的 `speedupdate.conf`，
把 `admin_password` 改成新的，重启服务端就行。

**很多人同时更新会把服务器打爆吗**

不会。`max_downloads` 控制同时下载的人数，超出的会收到「服务器忙，稍后重试」，客户端会自己重试。

## 已知限制

- 只处理 `mods/`、`shaderpacks/`、`resourcepacks/` 三个目录里的文件，`config/`、存档一概不碰
- 只支持 NeoForge
- 26.1 / 26.2 是 Minecraft 的新版本号规则（原来该叫 1.22），不是笔误
- 服务和游戏都靠客户端自己比版本号，防不了想搞事的人；定位是「给自己人用」

## 从源码构建

需要 JDK 21：

```bash
gradlew build
```

产物在 `build/libs/` 下。想改点东西的话，客户端源码在 `src/main/java/com/speedupdate/`，
服务端是仓库根目录的 `server.py`（同时也是打包进 jar 的那一份）。
